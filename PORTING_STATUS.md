# ArgentumForge Porting Status

## Scope

Target: Minecraft Forge 1.8.9 (Forge `1.8.9-11.15.1.2318-1.8.9`), MCP `stable_22`, Java 8, LWJGL 2. This is an experimental port, not a complete Argentum or Celeritas renderer. Terrain integration replaces `RenderGlobal`'s chunk factory and render container at runtime through reflection. Hooks that need code inside vanilla methods (particles, fonts) use Mixin 0.7.11, embedded in the jar and started through the manifest `TweakClass`, with `ArgentumForgeLoadingPlugin` as the `FMLCorePlugin`. There is no access transformer and no hand-written `IClassTransformer`.

**Validation status:** built with `./gradlew build` (15 unit tests pass) and exercised by `./gradlew runClient -PsmokeTest` in the Forge 1.8.9 dev client. See "Validation record" in `TECHNICAL_NOTES.md`. Rows marked "unverified" or "static" were not exercised at runtime.

## Feature matrix

Legend: **Connected** = called from a real Minecraft/Forge code path. **Partial** = connected, with documented gaps. **Disabled** = present but off by default or off by design. **Not implemented** = no source path.

| Master switch | Connected | `enableExperimentalRenderer` (default `false`) gates every feature except the font width cache. | - |
| In-game settings | Connected | Mods list -> ArgentumForge -> Config, or the "Open ArgentumForge settings" key (unbound by default). Forge `GuiConfig` over the three config categories. Done saves the file and calls `ArgentumConfig.sync()`; the terrain path installs or restores itself on the next client tick. | Some overlay-only options still need a world reload to take full effect. |
| Terrain integration (`terrainMode=integrated`) | Connected | `client/terrain/IntegratedTerrain` swaps `RenderGlobal.renderChunkFactory` (`field_175007_a`) and `renderContainer` (`field_174996_N`) for `ArgentumRenderChunkFactory` and `ArgentumVboRenderList`/`ArgentumDisplayListRenderList`, then calls `RenderGlobal.loadRenderers()`. Light logic mirrors `ChunkCache.getLightForExt`. | Tile-entity objects remain shared live references that block models may read on the worker, exactly as vanilla does; they are not immutable. Reads outside the 20^3 region (not expected from vanilla renderers) still fall back to the live `ChunkCache` path and are counted on F3. A pending cache keeps references to its chunks until it is consumed or discarded. |

Stale results are rejected by vanilla task-status checks. ArgentumForge adds: snapshot and cache paired to the exact task object and verified against world, `from`, `to` and `subtract` before use, release of every reservation on success, mismatch, cancellation, position change, GL deletion, renderer restore and client world unload (`WorldEvent.Unload` - `setWorldAndLoadRenderers(null)` keeps the old `ViewFrustum`), `terrainSnapshotsPerFrame` budget, a `terrainMaxPendingSnapshots` memory cap, and discard on new task, position change, `stopCompileTask` or `deleteGlResources`. Capture failures fall back per section, and snapshots are disabled after 16 failures. | No custom priority queue: vanilla's nearest-first queueing order is kept. Over-budget sections use vanilla's live-reading region cache. |
| Block meshing semantics | Connected (vanilla) | Vanilla/Forge `rebuildChunk` and `BlockRendererDispatcher` do the meshing: baked models, `ISmartBlockModel`, fluids, AO and lightmap coordinates, biome tint, `canRenderInLayer`, tile-entity collection, the visibility graph and translucent quad sorting. | Identical output to vanilla is expected but has not been verified. |
| Section visibility | Partial | Vanilla `setupTerrain` frustum and cave-culling BFS are unchanged. On top of that, `TerrainVisibilityFilter` drops a section layer when the bounds of the blocks that can render in *that layer* (Forge `canRenderInLayer`, captured per layer) of the installed compile result (plus a 1-block margin) are outside the left/right/top/bottom planes taken from the GL matrices at `ChunkRenderContainer.initialize`. Near/far planes are ignored. It draws when it is unsure. | Bounds are looked up lock-free: workers record them per `CompiledChunk`, and the `RenderChunk.setCompiledChunk` override (called when vanilla installs the result) publishes them in a volatile field. No GPU occlusion queries and no custom visibility graph: queries return results a frame or more late on this LWJGL 2 pipeline, which causes terrain popping on camera turns unless sections are drawn while results are pending, and vanilla's cave-culling BFS already removes most hidden sections. Plane capture assumes `setupTerrain` runs under the camera matrices (static reading of `EntityRenderer.renderWorldPass`). |

## FeatherOpt compatibility review (static only)

The `mixins.featheropt.json` and `mixins.featheropt.cond.json` configurations were inspected. `FeatherOptMixinPlugin.shouldApplyMixin` returns true and `getMixins` adds only the conditional list.

- None of the registered mixins target `RenderChunk`, `ChunkRenderContainer`, `VboRenderList`, `RenderList`, `IRenderChunkFactory`, `RegionRenderCache` or `TileEntityRendererDispatcher`. `MixinRenderGlobal_*` classes exist in the source tree but are not listed in either config.
- `inline.MixinChunkCache_AvoidCopying` redirects `EnumFacing.values()` inside `ChunkCache.getLightForExt`. Snapshot-backed caches override `getCombinedLight`, so that redirect is simply not reached for those builds. Over-budget sections still use vanilla `ChunkCache` with FeatherOpt's redirect.
- `inline.MixinBlockModelRenderer_AvoidCopying` and the Forge model-pipeline mixins still apply, because meshing still uses those classes.
- ArgentumForge does not disable itself when FeatherOpt is present. `disableExperimentalRendererWithFeatherOpt` (default false) turns off only the terrain path, and `disableOptionalEffectsWithFeatherOpt` only the overlay framebuffer effect.
- This review does not prove runtime compatibility.

## Mixin hooks

- No Forge 1.8.9 event fires inside `EffectRenderer.renderParticles` or `FontRenderer.getStringWidth`, so both hooks are Mixins. Targets are resolved through the generated refmap (`func_78874_a`, `func_180434_a`, `func_78256_a`, `func_110549_a`, `func_78264_a`).
- FeatherOpt and other Mixin-based clients also patch rendering classes. Whether any of them target the same two methods was not checked.
- `Minecraft.effectRenderer` is still not replaced, because replacing it would drop mod-registered particle factories.

## FeatherOpt white-screen report

No source-level cause could be confirmed without a log or runtime evidence. The relevant gates stay available: `disableExperimentalRendererWithFeatherOpt` (terrain only) and `disableOptionalEffectsWithFeatherOpt` (framebuffer effect only). No behavior was changed for this report.

## PR #18 review (closed, not merged)

Each proposal was checked against `main` and Forge 1.8.9; none was reused.

- **Async legacy meshing (`ChunkSnapshot` + executor in `ChunkMeshManager`): rejected.** The worker still calls `BlockFaceMesher.buildChunkMesh(world, ...)`, so it reads the live `World`, `Minecraft` block models and `TerrainLighting` world lookups off-thread. The executor's queue is unbounded and there is no world/revision check before publishing. Fixing it would mean a second background chunk system duplicating the integrated compiler, so the legacy overlay stays synchronous and comparison-only.
- **11-float `GlVbo` layout with lightmap UVs: rejected.** The meshers did not emit consistent lightmap values for every vertex. `draw()` never set a texture-coordinate pointer on `OpenGlHelper.lightmapTexUnit`, so the coordinates were never consumed. Integrated mode already gets real lightmap coordinates from vanilla `DefaultVertexFormats.BLOCK`.
- **`FontAndGlintOptimization`: rejected.** Nothing calls it. It sets blend/depth state, and a static flag can leave `GL_EQUAL` depth and additive blending active. It contains no font, HUD or glint caching.
- **Tile-entity loop and entity bounding-box check in `OptionalRenderHooks`: rejected.** Both compute values and then `continue` or do nothing; they have no effect. Block-entity culling already exists through the renderer wrapper.

## Not completed

- Measured frame-time benefit, visual parity and compatibility: these need a real client.
- GPU occlusion culling, and a custom section graph or priority scheduler.
- Font/text/name-tag/HUD/glint caching, item-model caching or batching, particle culling or batching, entity batching.
- A VBO-cached weather or cloud renderer at vanilla parity.
