# ArgentumForge Porting Status

## Scope

Target: Minecraft Forge 1.8.9 (Forge `1.8.9-11.15.1.2318-1.8.9`), MCP `stable_22`, Java 8, LWJGL 2. This is an experimental port, not a complete Argentum or Celeritas renderer. The project has no Mixin configuration, coremod, access transformer or `IClassTransformer`. Terrain integration replaces `RenderGlobal`'s chunk factory and render container at runtime through reflection.

**Validation status: nothing in this revision was compiled, built, unit-tested or run in Minecraft.** Every claim below comes from source inspection of this repository, the MCP 1.8.9 decompiled sources, the Forge 1.8.9 patches and userdev artifact (2318), the MCP `stable_22`/SRG mappings, and the upstream repositories named below.

## FeatherOpt compatibility review (static only)

The `mixins.featheropt.json` and `mixins.featheropt.cond.json` configurations were inspected. `FeatherOptMixinPlugin.shouldApplyMixin` returns true and `getMixins` adds only the conditional list.

- None of the registered mixins target `RenderChunk`, `ChunkRenderContainer`, `VboRenderList`, `RenderList`, `IRenderChunkFactory`, `RegionRenderCache` or `TileEntityRendererDispatcher`. `MixinRenderGlobal_*` classes exist in the source tree but are not listed in either config.
- `inline.MixinChunkCache_AvoidCopying` redirects `EnumFacing.values()` inside `ChunkCache.getLightForExt`. Snapshot-backed caches override `getCombinedLight`, so that redirect is simply not reached for those builds. Over-budget sections still use vanilla `ChunkCache` with FeatherOpt's redirect.
- `inline.MixinBlockModelRenderer_AvoidCopying` and the Forge model-pipeline mixins still apply, because meshing still uses those classes.
- ArgentumForge does not disable itself when FeatherOpt is present. `disableExperimentalRendererWithFeatherOpt` (default false) turns off only the terrain path, and `disableOptionalEffectsWithFeatherOpt` only the overlay framebuffer effect.
- This review does not prove runtime compatibility.

## Particles, fonts/HUD/glint: why still not implemented

- No Forge 1.8.9 event fires inside `EffectRenderer.renderParticles`, `FontRenderer.renderString`, `RenderItem.renderEffect` or `GuiIngame`. Per-particle culling, text-layout caching and glint state batching would each need an `IClassTransformer` coremod (manifest `FMLCorePlugin`, plus a separate dev-environment run configuration), with exact SRG descriptors at the call sites. That transformer could not be compiled or run under this phase's no-build rule. FeatherOpt already ships coremod mixins for rendering classes, so overlapping transformations need runtime verification. The transformer was therefore not added in this pass.
- `Minecraft.effectRenderer` was not replaced, because replacing it would drop mod-registered particle factories.

## FeatherOpt white-screen report

No source-level cause could be confirmed without a log or runtime evidence. The relevant gates stay available: `disableExperimentalRendererWithFeatherOpt` (terrain only) and `disableOptionalEffectsWithFeatherOpt` (framebuffer effect only). No behavior was changed for this report.

## PR #18 review (closed, not merged)

Each proposal was checked against `main` and Forge 1.8.9; none was reused.

- **Async legacy meshing (`ChunkSnapshot` + executor in `ChunkMeshManager`): rejected.** The worker still calls `BlockFaceMesher.buildChunkMesh(world, ...)`, so it reads the live `World`, `Minecraft` block models and `TerrainLighting` world lookups off-thread. The executor's queue is unbounded and there is no world/revision check before publishing. Fixing it would mean a second background chunk system duplicating the integrated compiler, so the legacy overlay stays synchronous and comparison-only.
- **11-float `GlVbo` layout with lightmap UVs: rejected.** The meshers did not emit consistent lightmap values for every vertex. `draw()` never set a texture-coordinate pointer on `OpenGlHelper.lightmapTexUnit`, so the coordinates were never consumed. Integrated mode already gets real lightmap coordinates from vanilla `DefaultVertexFormats.BLOCK`.
- **`FontAndGlintOptimization`: rejected.** Nothing calls it. It sets blend/depth state, and a static flag can leave `GL_EQUAL` depth and additive blending active. It contains no font, HUD or glint caching.
- **Tile-entity loop and entity bounding-box check in `OptionalRenderHooks`: rejected.** Both compute values and then `continue` or do nothing; they have no effect. Block-entity culling already exists through the renderer wrapper.

## Not completed

- Measured frame-time benefit, visual parity and compatibility: these need a real client.
- GPU occlusion culling, and a custom section graph or priority scheduler.
- Font/text/name-tag/HUD/glint caching, item-model caching or batching, particle culling or batching, entity batching.
- A VBO-cached weather or cloud renderer at vanilla parity.
